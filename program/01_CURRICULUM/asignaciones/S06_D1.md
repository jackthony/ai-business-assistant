## 5. Contrato (no se negocia)
Los nombres públicos van en inglés (`program/03_ARCHITECTURE/estandares.md` §3); los ejemplos y los textos para la clienta, en español peruano. Solo se fija el contrato: nombres, firmas y reglas de comportamiento. **La implementación y los ejemplos no están escritos aquí.**

### 5.1 `configs/hola_mujer/fewshot_objeciones.json`
- Forma: `{"meta": {...}, "items": [{"id": "...", "tipo": "...", "objecion": "...", "respuesta": "..."}, ...]}`.
- **Al menos 5 ejemplos** con ids únicos, y **al menos uno de cada tipo** `precio`, `consulta` y `descuento` (el cuarto tipo permitido es `otra`).
- Cada `respuesta` (lo que diría Hola Mujer) debe cumplir las **cuatro reglas** de `violations` (5.2): estilo (máximo 3 líneas con texto y como mucho 1 signo `?`), **lleva la marca `[1]`**, **no trae importes** ni **horas**.
- Las objeciones y las respuestas las **inventas tú**, como las diría una clienta real y como las contestaría una asesora cálida y breve. Sin nombres de clientas ni teléfonos.

### 5.2 `src/agents/fewshot.py`
- `FewShot`: modelo de Pydantic v2, inmutable (`frozen`), con `id: str` (solo minúsculas, dígitos y guion; de 3 a 40 caracteres: `^[a-z0-9-]{3,40}$`), `tipo: Literal["precio", "consulta", "descuento", "otra"]`, `objecion: str` y `respuesta: str` (ambas de al menos 3 caracteres).
- `load_fewshots(path: Path) -> list[FewShot]` — lee `{"items": [...]}`, valida cada ejemplo y devuelve la lista en el orden del archivo. Si dos ejemplos repiten el `id`, lanza `ValueError` **cuyo mensaje nombra el id repetido**.
- `violations(shot: FewShot) -> list[str]` — devuelve los códigos de lo que incumple `shot.respuesta`, **en este orden**: primero los que devuelve `check_reply_style` (tal cual: `empty`, `too_many_lines`, `too_many_questions`), luego `"no_citation"` (si falta la marca `[1]`), luego `"amount"` y luego `"hour"`. Lista vacía si cumple todo.
  - `amount`: la respuesta contiene `S/` seguido (con o sin espacios) de un dígito, o un número seguido de la palabra `soles` (sin importar mayúsculas).
  - `hour`: la respuesta contiene una hora con la forma `H:MM` o `HH:MM` (por ejemplo `15:30`).
- `render_fewshots(shots: list[FewShot]) -> str` — formato exacto: la línea
  `Ejemplos de cómo responder a objeciones (solo muestran el tono; los datos salen siempre de <fragmentos>):`
  seguida de una línea en blanco y de un bloque por ejemplo, separados por una línea en blanco. Cada bloque son dos líneas: `Clienta: <objecion>` y `Hola Mujer: <respuesta>`.

### 5.3 `src/agents/config.py`
- `TenantConfig` gana un campo `prompt_v2: str`.
- `load_tenant_config(tenant)` lo calcula así: `prompt_v2 = prompt + "\n\n" + render_fewshots(load_fewshots(<carpeta del tenant>/"fewshot_objeciones.json"))`, donde `prompt` es el prompt v1 compuesto **tal como ya lo carga #53**.
- **`prompt` no cambia**: sigue siendo el v1. Nada del agente en producción usa `prompt_v2` todavía.

### 5.4 `src/evals/compare_prompts.py`
- `CORPUS`: la ruta a `data/conversaciones/sinteticas_v2.jsonl`, calculada desde `__file__` (no desde la carpeta de trabajo).
- `Runner` = una función `(prompt_de_sistema: str, texto_de_la_clienta: str) -> str` (la respuesta del bot).
- `StyleSummary`: modelo inmutable con `total`, `compliant`, `too_many_lines`, `too_many_questions` y `empty` (todos enteros).
- `pick_conversations(path: Path, n: int = 10) -> list[str]` — elige mensajes de la clienta, de forma **determinista**:
  1. Solo filas con `escenario == "servicios"` y `rol == "user"`.
  2. Ordenadas por `(conversacion_id, turno)`.
  3. Se descarta el mensaje si, ya sin espacios en los extremos, tiene **menos de 3 palabras**, o su minúscula empieza con `hola`, `buen` o `[` (saludos y marcadores de medios), o es **repetido** (sin importar mayúsculas).
  4. Devuelve los primeros `n` que sobreviven, con su texto sin espacios en los extremos.
- `style_summary(replies: list[str]) -> StyleSummary` — usa `check_reply_style`. `compliant` cuenta las respuestas **sin ningún código**; `too_many_lines`, `too_many_questions` y `empty` cuentan las que traen ese código (una respuesta puede sumar en varias).
- `render_comparison(v1: StyleSummary, v2: StyleSummary) -> str` — tabla de Markdown con **este formato exacto** (sin salto de línea final):
  ```
  | Métrica | v1 | v2 |
  |---|---|---|
  | Respuestas | <total> | <total> |
  | Cumplen el estilo | <compliant> | <compliant> |
  | Más de 3 líneas | <too_many_lines> | <too_many_lines> |
  | Más de 1 pregunta | <too_many_questions> | <too_many_questions> |
  | Vacías | <empty> | <empty> |
  ```
- `make_live_runner() -> Runner` — conecta con Ollama y el RAG reales (como `build_default_graph`) y devuelve el ejecutor que arma el grafo con el prompt recibido y responde la pregunta. **No se prueba** (necesita Ollama); se ejecuta una vez en la M5.
- `main(argv: list[str] | None = None, runner: Runner | None = None) -> int` — la CLI `python -m evals.compare_prompts`:
  - Opciones: `--live` (bandera), `--n` (entero, por defecto 10) y `--corpus` (ruta, por defecto `CORPUS`).
  - **Sin `--live`**: escribe en **stderr** un mensaje que contiene `--live`, no llama al ejecutor y devuelve `2`.
  - **Con `--live`**: carga la configuración del tenant `hola_mujer`, usa `runner` (o `make_live_runner()` si es `None`), elige las preguntas con `pick_conversations(args.corpus, args.n)`, las corre **todas con `cfg.prompt` y todas con `cfg.prompt_v2`**, imprime con `render_comparison` y devuelve `0`.
  - El módulo termina con el bloque `if __name__ == "__main__":` que llama a `main()` y pasa su valor a `sys.exit`.
- **La tabla mide estilo, no calidad.** No dice si la respuesta es correcta ni útil.
